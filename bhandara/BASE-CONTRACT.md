# Bhandara Common·Tool 공개 계약

## 사용 가능한 실행 단위

- `paid-time-off` — 연차 발생·차감·사용원장·선택 Closing
- `worktime` — 스케줄·출입검증·근로사실 Excel
- `payroll` — 7종 입력, 별도 승인/정책 JSON, 급여대장·검토 JSON
- `workflow` — 기존 Tool 결과를 실행·검증·재사용하는 경량 연결
- `common-normalizer` — 매핑이 필요한 외부 원본의 독립 정규화

각 Tool은 다른 Tool 코드를 요구하지 않는 **독립 기능**이며, 필요한 경우에만 Workflow에서 순서를 정한다. 공통 라이브러리만 의존한다. Tool은 개인 JSON의 기간·경로를 사용하며 명령어 옵션에서 계산기간을 직접 변경하지 않는다.

## 공통 I/O와 검증 책임

- **Common** 직원정보 정본과 보안업체 매핑은 한 곳에서 관리한다.
- Excel 읽기는 엄격한 시트·헤더·자료형·수식 검사 및 기본 ID 보존을 따른다. 개별 Tool의 계약이 서로 다른 검증 정책을 가지고 있으므로 억지로 같은 형태로 정규화하지 않는다.
- 입력 파일은 반드시 정확한 경로를 지정한다. 파일명 추측·최근 파일 자동 선택·원본 덮어쓰기 금지.
- 산출물 실행별 `run_id`, 날짜 범위, SHA-256을 확인한다. 동일 ID 재실행은 덮어쓰지 않는다.
- Payroll 7종 단일시트 Excel, Worktime `WORKTIME` 10열, Payroll `PAYROLL` 한 시트는 현행 계약이다. [워크플로](WORKFLOW.md) · [급여 원본 파일 규격](payroll/input-files.json).

## 승인 경계

- 근태 사실은 지급 승인 근거가 아니며, 외부 근로구간·정책·승인자료를 자동 추론하지 않는다.
- PTO Closing은 외부에서 **확정한 원본**만 Payroll 확정 근거로 사용한다.
- 출력은 잠정 검토 자료로서 `NOT_APPROVED`다. 실제 급여 송금, 보험·세금 신고, 회사 원가계산까지 수행한다고 간주하지 않는다.
- 회사 비용(확인분)과 산재보험료는 관리자 범위이며 직원별 조회에서 제외한다.

## 운영·보안

실제 직원자료, 계약금액, 승인 전문·비밀번호는 공개 Git·로그에 저장하지 않는다. 캐시 TTL·Slack 업로드 권한/조회·실행 승인·답변 전송은 Portfolio 밖의 Gearbox/Hermes가 보증해야 한다. 신규 에이전트 연결은 아직 별도 운영 검증이 필요하며, `agent-config`는 사용자 명시적 재개 승인 전까지 변경하지 않는다.

테스트는 `python3 -B bhandara/_tests/run.py`로 한 번에 실행한다. 전체 Bhandara 계약 변경 때 Gearbox 기능/인프라 테스트를 별도로 실행한다.
